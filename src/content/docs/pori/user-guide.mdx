This guide covers normal day-to-day use of Pori.

## Before You Start

| Requirement                                    | How to Verify                                                                                                                                                                        | What to Look For                                                                                                                               |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Permission to make system changes              | Open Pori as your normal user in a desktop session with a polkit authentication agent.                                                                                               | You can authorize mount changes when prompted. You don't need to launch Pori with `sudo`.                                                      |
| Disk health (if you suspect filesystem errors) | On an unmounted ext4 partition, run `sudo e2fsck -n /dev/sdXN`, replacing `/dev/sdXN` with the partition you verified in `lsblk -f`. Use the appropriate tool for other filesystems. | The check reports no filesystem errors. The `-n` flag checks without making repairs.                                                           |
| Disk visible to the system                     | Run `lsblk -f`.                                                                                                                                                                      | The partition appears with its filesystem type and UUID.                                                                                       |
| Suitable mount point                           | Check the intended path, for example with `ls -ld /mnt/backup`.                                                                                                                      | Choose a new path or an empty directory so the mount doesn't hide existing files. systemd creates missing directories when it mounts the disk. |

## Mount a Disk

:::caution[Data Safety]

- **Double-check the device**: Pori shows disk sizes and labels, but verify you're selecting the correct physical disk.
- **Avoid system directories**: Never mount to `/home`, `/usr`, `/var`, or other system paths unless you know exactly what you're doing.
- **Unmount before unplugging**: Close files on the disk and stop its `.mount` unit with `sudo systemctl stop UNIT.mount`, replacing `UNIT.mount` with the actual unit name. Check that the disk is unmounted before disconnecting it. Pori's **Remove mount** deletes the persistent unit; use it only if you also want to forget the mount.

:::

1. Open Pori.
2. Select a drive that is not already mounted.
3. Click **Mount**.
4. In the dialog:
   - Confirm or edit the mount point.
   - (Optional) add a description.
   - Keep or adjust recommended mount options.
   - (Optional) add extra comma-separated options.
5. Click **Mount**.
6. Authenticate when prompted.

![Mount Dialog](../../../assets/screenshots/pori/pori_dialog.png)

If successful, Pori refreshes the device list and the disk appears as mounted.

## Mount Options

When creating a mount, Pori preselects the recommended options shown for the
detected filesystem. Review the checked options before saving. These are
examples of what the dialog offers, not a complete list:

| Filesystem | Example options                         | What they do                                                                                           |
| ---------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| ext4       | `noatime`, `errors=remount-ro`          | Skip access-time updates; remount read-only on filesystem errors. Ownership comes from the filesystem. |
| Btrfs      | `compress=zstd:3`, `noatime`            | Enable transparent compression and skip access-time updates.                                           |
| NTFS       | `windows_names`, `uid=$UID`, `gid=$GID` | Keep new filenames Windows-compatible and map ownership to your user and group.                        |
| exFAT      | `uid=$UID`, `gid=$GID`, `sync`          | Map ownership to your user and group; use synchronous writes if `sync` is selected.                    |
| UDF        | `unhide`, `uid=$UID`, `gid=$GID`        | Show otherwise hidden files and set the default user and group IDs.                                    |
| ZFS        | `defaults`, `x-gvfs-show`               | Use standard mount defaults and ask compatible file managers to show the mount.                        |

Pori replaces `$UID` and `$GID` with your numeric IDs before writing the mount
unit. The [tagged option list](https://github.com/Seafoam-Labs/Pori/blob/v0.2.0/Pori.Ui/src/helpers/options.zig#L24-L106)
shows the full set for this release.

### Extra Options

Add comma-separated options (e.g., `noexec,nosuid,ro` for read-only, no-execution access). These append to the recommended set.

## NTFS Confirmation

When mounting an NTFS disk, Pori shows a compatibility warning before continuing. You can cancel or proceed.

## What Pori Creates

For a mount point like `/home/alice/mnt/games`, Pori creates:

- Unit file: `/etc/systemd/system/home-alice-mnt-games.mount`
- Unit content mapping:
  - `What=/dev/disk/by-uuid/<UUID>`
  - `Where=<mount point you chose>`
  - `Type=<filesystem type>`
  - `Options=<selected options>`

Pori then runs:

- `systemctl daemon-reload`
- `systemctl enable --now <unit>`

:::note[What Pori Doesn't Modify]

Pori creates native systemd `.mount` units. It does **not**:

- Edit `/etc/fstab`
- Create `/etc/crypttab` entries (for encrypted disks — decrypt first with your distro's disk utility)
- Handle network mounts (NFS, SMB, SSHFS)
- Manage LVM or RAID (use on activated logical volumes only)

:::

## Best Practices

- **Use descriptive mount points**: _/mnt/backup-drive_ is better than _/mnt/sdb1_ (which changes between boots).
- **Use _/mnt_ or _/media_**: which are often used for mounting. You can also create a new directory like _/drives_, _/games_, etc. Don't do home directory mounts (_/home/$USER/mnt_) if multiple users need access.
- **Label your disks**: Use _e2label_ or _ntfslabel_ so Pori shows friendly names, not just _/dev/sdb1_.
- **Check UUID stability**: Pori uses _/dev/disk/by-uuid/_ which survives disk reordering. USB drives should keep consistent UUIDs.

## Verify or Troubleshoot

- Check unit status:
  - `systemctl status <unit>.mount`
- Check logs:
  - `journalctl -u <unit>.mount`
- If authentication fails, check that your session is running a polkit
  authentication agent and that the account you select can authorize the
  action. Use the credentials requested by the dialog. This is a polkit
  prompt, not a `sudo` prompt; don't retry by launching Pori with `sudo`.
- If a disk is missing:
  - Confirm it appears in `lsblk -f`.
